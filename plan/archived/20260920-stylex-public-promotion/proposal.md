# StyleX Public Promotion And RC

## Problem

The complete private StyleX candidate is implemented and verified, but public `@bridge/ui` exports still resolve to generated/brand baseline source. CSS ownership, registry proof and consumer integration must remain explicit release work rather than being hidden inside the completed private candidate proposal.

## Scope

- Promote accepted private candidate family into owned public source without editing generated Shadcn files.
- Preserve root/direct/subpath API and provider identity.
- Finalize the component/global/font CSS contract and scoped adapter packaging.
- Run full package, registry RC and Bridge Web integration proof.
- Review remaining foundation gate before any broad consumer migration.

## Out Of Scope

- Stable `latest` publication without reviewed RC proof.
- Bridge Web product-route migration beyond the bounded package fixture.
- Cue migration before Bridge Web approval.
- Changing application business state, routing, authorization or translation ownership.

## Success Criteria

- Public root/direct/subpath resolve to accepted owned implementation with no unsupported generated runtime path.
- Consumer needs no Tailwind or StyleX compiler/runtime setup beyond documented CSS import.
- Both CSS load order and portal/theme scope leave outside sentinel unchanged.
- Exact private-registry RC installs and passes Bridge Web fixture.
- Foundation readiness is reviewed explicitly before consumer migration.
